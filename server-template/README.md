# CopyLocker server

This project deploys the versioned `copylocker-worker` package without copying its Rust runtime. It
is generated by `copylocker init`, which renders the Worker name, product ID, D1/KV IDs, Secrets
Store ID, and optional API URL into `wrangler.jsonc` and `copylocker.json`.

## Provision and validate

Before initialization, provision:

- the D1 database and KV namespace whose IDs are passed to `copylocker init`;
- the Secrets Store whose 32-character ID is passed to `copylocker init`;
- the R2 bucket `<project-name>-archive`;
- `<project-name>-events` and `<project-name>-events-dlq` queues.

Then install the pinned JavaScript dependencies and validate the upload bundle:

```bash
npm install
copylocker deploy --project .
```

Without `--confirm`, `copylocker deploy` only runs Wrangler's local upload-bundle dry-run and writes
`.copylocker/dry-run.js`. `npm run check` performs the same template-level dry-run directly.

## First bootstrap

Migrations intentionally do not invent a vendor, product, or Admin credential. Create a protected
bootstrap bundle outside this project, preview the operation, and then confirm it:

```bash
copylocker bootstrap prepare \
  --project . \
  --vendor vendor-acme \
  --actor owner \
  --out /secure/copylocker-bootstrap.json

copylocker bootstrap apply --project . --bundle /secure/copylocker-bootstrap.json
copylocker bootstrap apply --project . --bundle /secure/copylocker-bootstrap.json --confirm
```

The confirmed command uploads `ADMIN_TOKEN_PEPPER` through Wrangler stdin, applies all remote D1
migrations, and conflict-checks the initial vendor/product/token rows. It is safe to rerun with the
same bundle. If the secret upload succeeded and a later D1 step failed, use `--confirm
--skip-secret-upload` with that exact bundle.

The bundle is mode 0600 and contains the plaintext Admin token and pepper. Move `admin_token` into
the environment variable named by `admin_token_env` in `copylocker.json`, then destroy the bundle
or escrow it in protected recovery storage. Never commit it, paste it into logs, or pass it on a
command line.

Bootstrap creates only the Admin token pepper. Provision every other bound secret used by your
deployment, including `SERVER_PEPPER`, `EPOCH_SIGNING_KEY`, `EPOCH_FAST_SIGNING_KEY`,
`VARIANT_PARAMS_KEY`, `ASSET_KEK_KEY`, and enabled payment webhook secrets. Secret values are
complete versioned JSON objects and never belong in `wrangler.jsonc`.

## Deploy and operate

```bash
copylocker deploy --project . --confirm
copylocker doctor --project . --check-api
```

`bootstrap apply --confirm` already runs the remote migrations. The confirmed deploy repeats the
migration check before deployment; use `--skip-migrations` only when a separately controlled step
has already applied the exact migration set.

Use stable, unique idempotency keys for every Admin mutation:

```bash
copylocker catalog push --project . --idempotency-key catalog-2026q1
copylocker policy push --project . --file policy.json --idempotency-key policy-v1
```

The queue consumer intentionally runs with one concurrent consumer so billing events cannot race.
Keep the minute Cron enabled: it resumes pending Admin side effects, audit publication, revocation
sequences, and subscription transitions after interrupted requests.

Do not place Root keys, Epoch keys, webhook secrets, Admin tokens, or pepper values in this
directory. Root generation and signing happen on the offline ceremony host; upload only the
Root-signed epoch certificate through the Admin API and the matching Worker secret JSON through
Secrets Store.
