# CopyLocker — 愿景与范围

## 1. 一句话定位

**CopyLocker 是一套「Serverless 优先、后量子加密、算法可插拔、半开源」的软件授权（License）基础设施**，
让独立开发者和中小软件团队可以在 30 分钟内为自己的 Web / Tauri / Electron 应用接上一套
达到商业级强度的授权与防盗版体系，且不必把授权强度建立在一份人人可读的开源算法之上。

## 2. 为什么做这件事

现有方案的问题：

| 方案 | 问题 |
|---|---|
| Keygen / Cryptolens / LicenseSpring 等 SaaS | 按量收费、数据不在自己手上、算法完全公开、无法做私有定制、无后量子路径 |
| 自研 Ed25519 签名 + 一个 `verify()` 返回 bool | 客户端一行 patch 即破解；无吊销、无席位、无时钟防护 |
| 商业加壳/VMP | 昂贵、只覆盖桌面原生、对 Electron/Web 无效、与 CI 冲突 |
| 开源 license 库 | 算法与校验点完全公开 → 通用 patcher/keygen 一次编写全网通用 |

CopyLocker 的核心主张：

1. **Serverless 自持**：跑在使用者自己的 Cloudflare 账号上，成本接近 0，数据自持，全球低延迟。
2. **后量子起步**：签名与密钥封装默认走 PQ/T 混合（经典 + 后量子），不留 "harvest now, decrypt later" 的债。
3. **算法槽位化（Crypto Suite Slots）**：算法是可替换的实现细节而非架构假设。默认提供开源参考套件，
   并提供一个**闭源私有套件**，使得「针对 CopyLocker 通用破解」不能自动等价于「针对某个厂商破解」。
4. **验证是「生产性」的，不是「判定性」的**：验证的产物是应用真正需要的密钥材料（Feature Key），
   而不是一个可被短路的 boolean。这是本方案与绝大多数开源 license 库的根本区别。
5. **半开源**：解决方案主体开源以获得可审计性与生态，私有算法套件闭源以获得非对称成本。

## 3. 目标用户

| 角色 | 场景 |
|---|---|
| 独立开发者 / 小团队 | 一个 Tauri 桌面工具，卖买断制 License Key，要能离线用、要能防止一个 key 传遍全网 |
| SaaS + 桌面客户端厂商 | 账号登录制，强制在线，按席位计费，需要能远程停用 |
| 内部/私有部署软件商 | 卖给企业客户，客户内网无外网，需要离线激活文件 + 到期强制续期 |
| 需要合规的团队 | 需要 PQC 迁移证据、审计日志、密钥轮换流程 |

## 4. 范围（In Scope）

### 4.1 服务端
- Cloudflare Workers 上的 License Server（Rust / workers-rs）
- 产品、版本、License、席位（Seat）、设备（Machine）、订单、吊销的完整生命周期
- 激活 / 校验 / 心跳 / 续期 / 停用 / 转移（Transfer）
- 离线激活请求-响应文件签发（air-gapped 支持）
- 管理 API + CLI + 最小化 Web 控制台
- 审计日志、异常检测（同一 key 的地理/指纹异常并发）

### 4.2 客户端
- `copylocker-core`：与宿主无关的 Rust 核心状态机
- Tauri v2 插件（`tauri-plugin-copylocker`）
- Electron 原生模块（napi-rs，主进程运行，含 preload 桥）
- C ABI（`copylocker-ffi`），供 Qt/Flutter/其他宿主接入
- Web SDK：Rust → WASM 核心 + TypeScript 触发层与二段变换层
- 本地安全存储（Keychain / DPAPI / secret-service / AEAD 文件回退）
- 设备指纹（可插拔）
- 时钟回拨防护、离线宽限期、吊销传播

### 4.3 构建期工具链
- `@copylocker/unplugin`：构建产物分片摘要 + 签名清单（IntegrityManifest）注入，支持自定义签名算法
- `@copylocker/guard`：运行时自校验、`@guarded` 装饰器、函数体完整性校验
- `copylocker-cli`：密钥仪式、License 签发、清单签名、凭证检视、KAT 生成
- `copylocker-seal`：把应用资产/代码分片用 Feature Key 加密，使「不通过验证就拿不到功能」

### 4.4 授权模式
- **Mode O — 离线优先混合模式**：一次性离线激活 + 有网即校验 + 判非法立即 deactivate
- **Mode E — 强制在线模式**：首次必须在线激活（账号 + 在线数字凭证），周期内必须至少成功在线校验一次，否则锁定

### 4.5 授权模型（五个正交轴，见 ADR-0009）
- 权益：Feature / FeatureGroup / Tier / Grant / Limits
- 有效期：永久 / 限时 / 订阅（含 dunning 宽限与永久回退）/ 试用
- 版本范围：不限 / semver / **按发布日期封顶** / 锁定特定版本
- 席位、模式
- 11 个开箱预设 + 配置预览器（CLI + 控制台）

### 4.6 版本治理（见 ADR-0008）
- 每个发布注册为 Release，派生独立变体（编码、FK info、绑定变换、离线验证参数）
- 版本级吊销：`warn` / `force_upgrade` / `revoke`，把破解的爆炸半径关进单个版本
- `security_floor` 单调基线防降级；跨版本兼容矩阵与永久保留的历史 KAT

### 4.7 授权分析（见 ADR-0007）
- **T0 协议派生（默认开启，零额外采集）**：激活数、签到设备、离线/在线比例、版本分布、席位利用率、流失与转化
- **T1 聚合遥测（默认关闭，需同意）**：会话计数、时长分桶、功能使用计数
- HLL 草图排重、k-匿名抑制、Admin API 与看板

### 4.8 管理控制台与法律配套
- SvelteKit + shadcn-svelte 控制台（独立 Worker，经 Service Binding 调 API）
- 法律配套包：数据清单、隐私政策章节、同意文案、DPA/ROPA/DPIA/DSR/EULA 模板

## 5. 非目标（Out of Scope）

明确**不做**的事，避免范围蔓延：

- ❌ **不做支付/计费**。只提供 Webhook 入口与 Admin API，接 Stripe/Paddle/Lemon Squeezy 由使用者自己完成。
- ❌ **不做通用代码混淆器/加壳器**。混淆是可选的第三方步骤，我们只定义接口与推荐配置。
- ❌ **不承诺"不可破解"**。见 §7 诚实声明。
- ❌ **不做 DRM 内容保护（视频/音频）**。
- ❌ **不做 iOS/Android 原生 SDK**（v1 范围外，架构上通过 `copylocker-ffi` 预留）。
- ❌ **不自研分组密码/哈希原语**。私有套件是对标准原语的**组合、参数化与绑定方式**的私有化，不是自创 S-box 级别的密码学。（见 ADR-0004）
- ❌ **v1 不做多租户 SaaS 托管服务**。产品形态是「你部署到你自己的 Cloudflare」。

## 6. 成功标准

| 维度 | 指标 |
|---|---|
| 接入成本 | 新项目从 0 到完成一次成功激活 ≤ 30 分钟；桌面端接入 ≤ 20 行代码 |
| 性能 | 在线校验 P95 < 120ms（全球）；客户端本地校验 < 5ms；WASM 核心 gzip 后 < 350KB |
| 可用性 | 客户端在服务端完全宕机时，仍可在宽限期内正常工作（Mode O）；服务端 SLO 99.9% |
| 成本 | 10 万活跃设备 / 月，Cloudflare 账单 < $20 |
| 安全 | 通过内部红队 5 类攻击场景；私有套件泄露不导致 License 伪造（Kerckhoffs 合规） |
| 生态 | 开源仓库可独立编译运行（不依赖私有套件），CI 全绿 |

## 7. 诚实声明（必须写进 README 和文档）

> **客户端侧的所有防护都是「防篡改可发现（tamper-evident）」而非「防篡改不可能（tamper-proof）」。**
> 攻击者对自己机器上运行的代码拥有完全控制权，这是物理事实，任何方案都无法改变。
>
> CopyLocker 的设计目标不是让破解不可能，而是：
> 1. 让**通用破解**（一次编写、全网通用）不可行 —— 通过每厂商独立的算法参数与密钥；
> 2. 让**破解成本**高于目标软件的价格 —— 通过 Feature Key 派生使得「短路验证」等价于「重新实现被加密的功能」；
> 3. 让**破解可被发现** —— 通过在线校验、指纹异常检测、审计日志；
> 4. 让**破解可被回收** —— 通过吊销 epoch 与强制在线窗口。
>
> 安全性**绝不**建立在私有算法的保密性之上（Kerckhoffs 原则）。私有套件泄露后，
> 系统的安全性降级为「与开源参考套件等同」，而不是「被攻破」。

## 8. 关键设计原则

1. **Kerckhoffs 优先**：先设计一个算法全公开也安全的系统，再叠加私有套件作为纵深防御。
2. **算法敏捷（Crypto Agility）**：所有密码学操作通过 trait 抽象，凭证格式携带 `suite_id`，
   支持多套件并存与灰度迁移。永远不要在协议里硬编码算法名。
3. **验证产物化**：`verify()` 不返回 `bool`，返回 `Credential` 与由其派生的密钥材料。
4. **失败安全（Fail-Secure）vs 可用性平衡**：网络失败 → 宽限期（fail-open with deadline）；
   密码学失败 / 明确吊销 → 立即失效（fail-closed）。这两类必须在代码里严格区分。
5. **零信任客户端**：服务端从不相信客户端上报的任何东西（时间、指纹、版本），只相信自己签的东西。
6. **最小可信计算基（TCB）**：客户端 TCB = WASM/原生核心中的验签与密钥派生路径，尽可能小、尽可能难替换。
7. **可离线开发**：本地 `wrangler dev` + 本地开发密钥即可完成全链路开发，不依赖线上环境。
