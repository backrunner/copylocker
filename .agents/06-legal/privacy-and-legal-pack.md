# 隐私与法律配套包（Privacy & Legal Pack）

> ⚠️ **免责声明（必须原样出现在每一份模板的顶部）**
>
> 本目录提供的所有文档是**工程团队编写的技术性模板**，用于降低 Vendor 起草合规文件的成本。
> 它们**不是法律意见**，不构成律师-客户关系，也不保证在任何司法辖区下的合规性。
> Vendor 在使用前**必须**由具备相应资质的法律顾问审阅并根据自身业务、数据流与适用法律修改。
> CopyLocker 项目方对使用这些模板产生的任何法律后果不承担责任。

需求：NFR-COMP-*、FR-TLM-*、ADR-0007

## 1. 为什么由我们提供模板

Vendor 开启分析功能时面临的真实障碍不是技术，而是"我需要在隐私政策里写什么"。
我们比 Vendor 更清楚 SDK 到底采集了什么、传到哪里、保留多久 —— 所以我们提供**准确的事实描述**，
Vendor 的律师在此基础上补齐司法辖区相关的表述。

**我们提供事实，律师提供合规判断。** 这是模板的定位。

## 3. 数据清单（Data Inventory）—— 核心事实表

这是所有其他文档的基础。**必须与代码保持同步**，由 CI 校验（见 §7）。

### 3.1 T0 协议派生（默认开启，授权功能必需）

| 字段 | 类型 | 是否个人数据 | 目的 | 保留 |
|---|---|---|---|---|
| `machine_id` | 服务端分配的随机假名 | 假名化数据 | 席位管理、防重复激活 | 设备释放后 90 天 |
| `fingerprint` | HMAC-SHA256 摘要（不可逆） | 假名化数据 | 设备识别、防复制 | 同上 |
| `device_attrs`（可选） | 规范化硬件属性 | **个人数据** | 指纹容差匹配（换硬件不失效） | 同上；**默认不上报** |
| `license_id` / `product_id` / `policy_id` | 标识符 | 与订单关联时为个人数据 | 授权判定 | License 生命周期 |
| `app_version` / `sdk_version` / `release_id` / `variant_id` | 版本字符串 | 否 | 兼容性判定、版本分布 | 3 年（聚合） |
| `os` / `arch` | 字符串 | 否 | 兼容性、分布统计 | 3 年（聚合） |
| `activation_path` | 枚举 | 否 | 离线/在线比例统计 | 3 年（聚合） |
| `cf.country` | 国家代码 | 低敏感 | 地理分布、异常检测 | 3 年（聚合） |
| 服务端时间戳 | 整数 | 否 | 有效期判定、活跃统计 | 同上 |
| IP 地址 | — | **个人数据** | **仅用于限流，不落库、不入分析** | 不保留（仅内存中的限流计数） |
| `account_id` / `email`（Mode E） | 标识符 | **个人数据** | 账号绑定 | 账号注销后 30 天 |

### 3.2 T1 聚合遥测（默认关闭，需同意）

| 字段 | 类型 | 目的 |
|---|---|---|
| `session_count` | 整数计数 | 使用频次 |
| `session_duration_histogram` | 4 个分桶的计数 | 使用深度（**不含精确时长、不含时间戳**） |
| `feature_hits` | 白名单内 feature 的计数 | 功能采纳率 |
| `days_active` | 0–28 的整数 | 活跃天数 |
| `consent_version` | 整数 | 同意版本记录（合规证据） |

**明确不采集**：事件时间戳序列、操作顺序、用户输入内容、文件名/路径、
剪贴板、屏幕内容、联系人、位置（GPS）、浏览历史。

### 3.3 数据流与处理者

```
终端用户设备 ──HTTPS──▶ Vendor 自有的 Cloudflare 账号
                          （Workers / D1 / Durable Objects / KV / R2 / Queues）
```

**关键事实（对 Vendor 的销售价值，也是合规优势）**：

- 数据**只**流向 Vendor 自己的 Cloudflare 账号。
- **CopyLocker 项目方不接收、不存储、不聚合任何终端用户数据。**
- 唯一的子处理者是 **Cloudflare, Inc.**（Vendor 与 Cloudflare 之间已有的 DPA 覆盖）。
- 无第三方分析 SDK、无广告 SDK、无数据经纪。

这段话应当逐字出现在 DPA 附件与隐私政策模板中。

### 3.4 数据本地化

Vendor 可通过 Cloudflare Jurisdictional Restrictions 约束 Durable Object 的落地区域
（如 `eu`、`fedramp`）。文档站提供配置指引。D1 与 R2 的区域策略同理。

## 4. 法律基础（GDPR 语境，供律师参考的起点）

| 层 | 建议的法律基础 | 论据 |
|---|---|---|
| **T0** | 合同履行（Art. 6(1)(b)）+ 正当利益（Art. 6(1)(f)，防盗版部分） | 授权验证是履行软件许可合同所必需；无此处理则无法交付授权的软件 |
| **T1** | **同意**（Art. 6(1)(a)） | 使用统计非履约必需，属于可选的产品改进目的 |
| **T2** | **同意** + 可能需要 DPIA | 事件级数据的重识别风险更高 |

> 注意：某些辖区（如欧盟的 ePrivacy 指令及其本地实施）对**终端设备上的信息存取**
> 有独立于 GDPR 的同意要求，可能覆盖到 T0 中的本地存储与设备属性读取。
> **这必须由 Vendor 的律师判断**，模板中会标注该风险点。

## 5. 同意管理（T1/T2）

### 5.1 SDK 侧的机制

```ts
const cl = await CopyLocker.create({
  telemetry: {
    tier: 'T1',
    consent: () => consentStore.get('analytics'),   // 每次上报前同步调用
  },
})
```

- SDK **每次**上报前调用 `consent()`，返回 falsy 则不上报。
- `consent_version` 随上报发送，服务端记录 → 形成合规证据链。
- 用户撤回同意 → 下次上报即停止；服务端提供 `POST /v1/admin/telemetry/purge?machine_id=`
  删除该设备已上报的 T1 数据。
- **未提供 `consent` 却设置 `tier: 'T1'` → SDK 初始化报错**（而非警告）。这是刻意的防呆。

### 5.2 同意 UI 文案模板要点

- 明确区分「授权验证」（必需，不可关闭）与「使用统计」（可选）。
- 不使用暗黑模式（预勾选、拒绝按钮弱化、"稍后提醒"循环）。
- 提供随时撤回的入口，且撤回与同意的操作成本对等。
- 说明关闭统计**不会**影响软件功能。

模板提供 zh-CN / en / de / ja 四语版本。

## 6. 数据主体请求（DSR）操作手册

| 请求 | 操作 | SLA |
|---|---|---|
| **访问 / 导出** | `copylocker dsr export --machine <id>` 或 `--account <id>` → 生成 JSON 包 | 30 天 |
| **删除** | `copylocker dsr delete --machine <id>` → DO 删除 + D1 投影删除 + R2 raw 清理 + 审计日志 PII 替换为 tombstone | 30 天 |
| **更正** | Admin API 修改 `metadata` | 30 天 |
| **反对处理 / 撤回同意** | 关闭 T1；T0 无法关闭（合同履行必需）→ 提供解释话术 | 立即 |
| **可携带性** | 同"导出" | 30 天 |

### 6.1 删除的边界（必须写进隐私政策）

| 数据 | 删除后 |
|---|---|
| `machines` 明细、`activations`、R2 raw | ✅ 删除 |
| 审计日志中的 PII 字段 | ✅ 替换为 tombstone（保留哈希链完整性，见 `data-model.md`） |
| **HLL 聚合草图与 rollup 计数** | ❌ **不回溯修改** |

**理由（需要在政策中解释）**：聚合草图不含个人数据（是不可逆的概率性数据结构），
且回溯修改会破坏历史统计的可比性与审计完整性。
删除请求执行后，该设备不再计入**未来**的聚合。

这条必须写清楚，否则会被质疑"删除不彻底"。

### 6.2 审计日志的保留 vs 删除张力

审计日志出于**防抵赖**目的需要保留（可能有法律要求），但含有个人数据。
处理方式：PII 字段替换为 tombstone，保留 `machine_id`（假名）与哈希链。
若 Vendor 的辖区要求更彻底的删除，提供 `--purge-audit` 选项（会破坏哈希链，需记录破链点）。

## 7. 与代码的一致性保证

**模板最大的风险是与实现漂移** —— 隐私政策写着不采集 X，代码却采集了 X。

CI 门禁 `legal-sync`：

```
1. SDK 中所有上报字段由一份 schema 单一来源定义（copylocker-types::TelemetryFields）
2. data-inventory.md 中的字段表由该 schema 自动生成（xtask gen-data-inventory）
3. CI 校验生成结果与提交的文档一致；不一致则失败
4. 新增任何上报字段 → 必须同时更新 schema → 文档自动更新 → 触发法律审阅标记
```

**任何新增采集字段的 PR 必须打 `needs-legal-review` 标签**，
并在 CHANGELOG 的"隐私影响"小节中说明。

## 9. 反滥用声明（重要的伦理边界）

CopyLocker 的分析能力**只用于授权管理与产品决策**。我们在设计上刻意排除了以下能力，
并在文档中明确声明**不会**添加：

- ❌ 跨应用/跨 Vendor 的用户追踪或数据关联
- ❌ 广告定向或数据变现
- ❌ 采集用户内容（文件、输入、剪贴板、屏幕）
- ❌ 精确地理位置（GPS）
- ❌ 静默的、无法被 Vendor 审查的采集（所有字段公开列出）
- ❌ 把指纹用于授权管理之外的目的

若有 Vendor 要求上述能力，明确拒绝并说明理由。
这不只是伦理立场 —— 一旦被发现具备这些能力，整个方案在企业客户处的可信度会归零。
